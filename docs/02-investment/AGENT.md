당신은 숙련된 프론트엔드 개발자입니다.
첨부한 hana 폰트를 적절히 활용하여
기존 hana-spot-pod-fe 프로젝트에 ‘hana spot pod’ 서비스의
‘투자안 선택 및 투자 확인’ 모바일 프로토타입을 구현해주세요.

먼저 프로젝트 구조와 기존 구현을 확인하고, 기존 코드 스타일과
내비게이션 구조를 활용해주세요.

1. 서비스 배경

hana spot pod는 여러 사람이 모임(Pod)을 만들고 돈을 모아,
대표자가 공동으로 투자하는 서비스입니다.

이번 구현에서는 다음 사항이 이미 완료됐다고 가정합니다.
- 모임 생성
- 참여 회원 설정
- 공동 투자금 조성
- 모임의 투자 성향 선택: 안정 / 균형 / 공격 중 하나
- 투자안 통과 기준 인원수 설정

로그인, 모임 생성, 투자 성향 설정 화면은 구현하지 않습니다.

2. 개발 환경과 범위

- React Native + Expo + TypeScript
- 기존 프로젝트에서 사용하는 패키지와 구조를 우선 활용
- Expo Go에서 실행 가능하도록 구현
- 모바일 화면과 터치 조작을 기준으로 설계
- 데모에 필요한 수준으로 간단하게 구현
- 불필요한 라이브러리, 복잡한 추상화, 백엔드 구축은 피할 것
- AI 추천, 하나증권 연계, 회원 투표 데이터는 목 데이터로 구현
- 실제 금융 API 연동, 주문 전송, 결제, 자금 이동은 구현하지 않음
- 최종 범위는 ‘투자 확인’ 화면까지이며 투자 실행 완료 화면은 만들지 않음

3. 디자인 지침

/reference 경로 하위에 준비된 하나머니 서비스 홍보 이미지를
직접 확인하고 색상, 타이포그래피, 카드 스타일, 여백 등
전체적인 시각적 분위기를 참고해주세요.

홍보 이미지의 구성을 그대로 복사하지 말고,
모바일 앱에서 사용하기 편한 UI로 재구성해주세요.

가장 중요한 원칙:
- 모든 화면과 기능은 직관적으로 이해할 수 있어야 함
- 한 화면에 너무 많은 정보나 기능을 몰아넣지 말 것
- 화면마다 사용자가 해야 할 핵심 행동을 명확하게 제시
- 부가 정보는 상세 화면에서 제공
- 주요 버튼의 위치와 문구를 일관되게 유지
- 선택, 미선택, 제출 완료, 후보 등록 상태를 명확하게 구분
- 색상만으로 상태를 전달하지 말고 텍스트나 아이콘도 사용
- 화면 전환은 자연스럽고 절제된 트랜지션 적용
- Safe Area, 작은 화면, 스크롤, 하단 버튼 영역을 고려

4. 핵심 업무 규칙

- 투자안 하나는 ETF 한 종목을 의미함
- 사용자는 여러 ETF에 복수로 투표할 수 있음
- 동일 회원이 같은 ETF에 중복 투표할 수는 없음
- 각 ETF의 득표 인원이 모임에 설정된 통과 기준 인원수를
  ‘초과’하면 투자 후보로 등록됨
- 예: 통과 기준이 3명이면 4명 이상이 투표해야 후보가 됨
- 기준 충족은 투자 후보 등록을 의미하며,
  최종 투자 승인이나 자동 주문 실행을 의미하지 않음
- 여러 ETF가 동시에 후보가 될 수 있음
- 후보 등록 전후 상태와 득표수를 화면 간 일관되게 반영

미정 사항은 다음 데모 기본값을 적용:
- 선택 개수 제한 없음
- 최소 1개를 선택해야 투표 제출 가능
- 기존 득표수는 목록에서 공개
- 제출 전에 선택 변경 가능
- 제출 후에는 재투표와 수정 기능을 구현하지 않음
- 대표자가 후보 ETF 중 복수 개를 선택해 투자 확인 화면으로 이동
- ETF별 투자 비중은 이번 범위에서 설정하지 않음
- 대표자 여부는 목 데이터로 관리하며,
  대표자가 아닌 회원에게는 투자 확인 진행 버튼을 표시하지 않음

이 기본값은 쉽게 변경할 수 있도록 상수와 목 데이터로 분리해주세요.

5. 화면 구성

A. 투자안 목록

목적:
모임의 투자 성향에 맞춰 AI가 제안한 ETF를 살펴보고,
마음에 드는 종목을 복수 선택한다.

표시 내용:
- 모임명
- 모임의 투자 성향
- AI 추천 투자안이라는 안내
- ETF 카드 목록
- 선택한 투자안 개수
- ‘투표 제출’ 버튼
- 직접 투자안 추가를 암시하는 ‘+’ 버튼

ETF 카드의 핵심 정보:
- ETF 상품명
- 주요 투자 대상 또는 짧은 설명
- 위험도
- AI 추천 이유 한 줄
- 현재 득표수와 후보 등록 상태
- 명확한 선택 컨트롤

동작:
- 카드 본문을 누르면 상세 화면으로 이동
- 선택 컨트롤을 누르면 선택 상태만 변경
- 상세 이동과 선택 동작이 충돌하지 않도록 구현
- 선택 상태는 상세 화면 방문 후에도 유지
- 아무것도 선택하지 않으면 제출 버튼 비활성화
- ‘+’ 버튼을 누르면 ‘직접 투자안 만들기는 준비 중입니다’
  안내를 표시하고 실제 생성 기능은 구현하지 않음

B. 투자안 상세

목적:
ETF를 이해하고 투표 여부를 판단한다.

표시 내용:
- 상품명과 투자 대상
- 위험도
- AI 추천 이유
- 주요 특징
- 운용보수 등 판단에 도움이 되는 기본 정보
- 현재 득표수
- 후보 등록에 필요한 조건
- ‘선택하기’ 또는 ‘선택 해제’ 버튼

동작:
- 목록과 선택 상태를 공유
- 뒤로 이동해도 기존 선택 유지

상품 정보와 수치는 데모용 데이터가 아니라 실제 데이터 처럼 느껴지게 표시해주세요.
과거 수익률은 이번 데모의 필수 정보가 아닙니다.

C. 투표 결과 및 후보 목록

목적:
투표 제출 결과와 후보가 된 ETF를 확인한다.

표시 내용:
- 투표 제출 완료 안내
- 각 ETF의 득표수
- 설정된 통과 기준
- 후보 등록 / 기준 미충족 상태
- 투자 후보 목록
- 대표자에게 ‘투자 확인으로’ 버튼

동작:
- 제출한 ETF마다 현재 회원의 표를 1표씩 반영
- 중복 제출로 득표수가 증가하지 않도록 처리
- 대표자는 후보 중 투자 확인 대상으로 복수 선택 가능
- 후보가 없으면 이유와 안내를 표시
- 후보를 선택하지 않으면 투자 확인 버튼 비활성화
- 데모에서 후보 등록 여부를 확인할 수 있도록
  기준 직전 ETF와 기준 미충족 ETF를 목 데이터에 포함

D. 투자 확인

목적:
대표자가 선택한 투자 후보와 모임 정보를 검토한다.

표시 내용:
- 모임명
- 대표자 정보
- 모임의 투자 성향
- 공동 투자 가능 금액
- 선택한 ETF 목록
- 각 ETF의 투표 결과와 후보 등록 근거
- ‘데모에서는 실제 주문이 진행되지 않습니다’ 안내

이 화면이 이번 프로토타입의 마지막 단계입니다.
공동 투자 가능 금액을 실제 주문 금액이나 ETF별 배분 금액으로
표현하지 마세요. 투자 실행 버튼과 실행 완료 화면은 만들지 말고,
이전 화면으로 돌아가 선택을 변경할 수 있게 해주세요.

6. 목 데이터와 상태 관리

다음 데이터를 타입으로 정의하고 한곳에서 관리해주세요.
- 모임
- 회원 및 대표자 여부
- 투자 성향
- 공동 투자 가능 금액
- 통과 기준 인원수
- ETF 투자안
- 회원별 투표
- 현재 회원의 선택 상태
- 투자 확인 대상 ETF

목 데이터는 회원 수와 득표수가 서로 모순되지 않게 구성해주세요.
투표 제출 이후 목록, 상세, 결과 화면의 득표수와 후보 상태는
같은 데이터에서 계산되도록 구현해주세요.

데모 상태는 앱 실행 중 메모리에서 유지하면 충분합니다.
별도 서버나 영구 저장은 필요하지 않습니다.

7. 구현과 검증

- 기존 코드에서 재사용할 수 있는 컴포넌트를 먼저 확인
- 목 데이터 기반의 정상 흐름을 끝까지 연결
- 필요한 로딩, 비활성화, 빈 상태만 간단히 구현
- 과도한 기능이나 범위 밖 화면을 추가하지 말 것
- 기존 프로젝트의 타입 검사 및 관련 검사 명령을 실행
- 복수 선택, 상세 화면 왕복, 중복 제출 방지,
  기준 인원수 초과 판정, 후보 없음, 대표자 권한,
  투자 확인 화면까지의 흐름을 확인

구현 후에는 다음을 간단히 설명해주세요.
- 구현한 화면과 사용자 흐름
- 적용한 데모 기본값
- 실행 방법
- 확인한 검사 결과와 남아 있는 제한사항
